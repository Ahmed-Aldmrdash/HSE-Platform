# أدوات الترجمة (AR / EN)

الواجهة كلها تمر على `T()` في `public/app.js`، والقاموس مضمَّن داخل نفس الملف
كـ `I18N_STRINGS`. مفتاح القاموس هو **النص العربي نفسه**، فأي نص جديد بدون
ترجمة يظهر عربيًا كما هو بدل أن يختفي.

`dictionary.json` هنا هو المصدر المرجعي للقاموس — عدِّله ثم أعد دمجه في
`public/app.js` (سطر `const I18N_STRINGS = {...};`).

## السكربتات

| السكربت | الغرض |
|---|---|
| `audit-coverage.js` | يطبع كل نص عربي في `public/app.js` **لا** يمر على `T()`، مصنَّفًا حسب السياق. شغّله بعد أي تعديل على الواجهة. |
| `scan-server-strings.js` | يطبع النصوص العربية في `server.js` التي تصل للمتصفح وليس لها ترجمة (رسائل الأخطاء والإشعارات). |
| `wrap-arabic-strings.js` | يلفّ نصوص العرض العربية بـ `T()` تلقائيًا عبر تحليل AST. `--in-place` يكتب فوق `public/app.js` مباشرة. |

```bash
node tools/i18n/audit-coverage.js
node tools/i18n/scan-server-strings.js
node tools/i18n/wrap-arabic-strings.js            # معاينة فقط
node tools/i18n/wrap-arabic-strings.js --in-place # تطبيق
```

## ما الذي لا يُترجَم عمدًا

- **قيم `value="..."` في HTML** — دي القيمة المخزَّنة في قاعدة البيانات
  والمقارَنة في الكود (`نعم` / `مطابق` / `موظف`). ترجمتها تكتب إنجليزي في
  قاعدة البيانات وتكسر المقارنات. المعروض للمستخدم فقط هو الذي يُترجم:
  `<option value="مطابق">${T("مطابق")}</option>`.
- **قيم الفلاتر** (`currentFilter` وأخواتها) — نفس السبب: `onclick`
  يمرر القيمة العربية، و`${T(o)}` يعرض الترجمة.
- **مفاتيح كائنات التصدير** (`'تاريخ الحذف': ...`) — عناوين أعمدة ملفات
  Excel/PDF، تبقى عربية لأن المستندات الرسمية عربية.
- **بيانات المستخدمين** — الأسماء، أوصاف البلاغات، عناوين المحاضرات. دي
  نصوص حرّة كتبها الناس، تظهر كما أُدخلت في اللغتين.

بعد أي تعديل على `public/app.js` شغّل `npm run build:assets` لأن الصفحة
تحمّل `app.min.js` وليس `app.js`.
